Deploying Metayaar and installing it on every device

This guide puts the store, admin panel and API on a server, publishes the desktop app for Windows, macOS and Linux, and installs the Android app on glasses that block APK installs on the device itself.

Docker ComposePHP 8.4 · LaravelPostgreSQL 17Next.jsElectronadb

Examples use metayaar.com, admin.metayaar.com and api.metayaar.com, and the project folder /var/www/ecoshaar/metayaar. Replace them with yours.

Part 1

Deploy the server

Everything runs from compose.yaml in the project root. The server only needs Docker; you don't install PHP, Node, PostgreSQL or nginx yourself.

Before you start

  • Server: Ubuntu 24.04, 2 CPU cores and 4 GB RAM at minimum (8 GB recommended, because building Next.js uses a lot of memory), 40 GB disk or more.
  • DNS: A records for metayaar.com, www.metayaar.com, admin.metayaar.com and api.metayaar.com pointing to the server IP.
  • Firewall: open only ports 22, 80 and 443.
  • Accounts: a MsgWay API key and OTP template ID for SMS, and SMTP details for email.
Don't add ports. Docker opens published ports directly in iptables, and ufw does not block them. Only nginx publishes ports. Port 8080 is bound to 127.0.0.1 so the website build can reach the API; never publish the database or Next.js.

Install Docker and get the code

sudo apt update
sudo apt install -y docker.io docker-compose-v2 git
sudo usermod -aG docker $USER     # log out and back in once
docker compose version

For a server in Iran, if pulling images from Docker Hub fails, add a registry mirror:

sudo tee /etc/docker/daemon.json <<'JSON'
{ "registry-mirrors": ["https://docker.arvancloud.ir"] }
JSON
sudo systemctl restart docker

If the server has 4 GB of RAM or less, add a 4 GB swap file so the build doesn't get killed:

sudo fallocate -l 4G /swapfile && sudo chmod 600 /swapfile
sudo mkswap /swapfile && sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab

Then clone the repository. The folders back, website, admin, docker and the file compose.yaml must be in the root.

sudo mkdir -p /var/www/ecoshaar/metayaar
sudo chown $USER: /var/www/ecoshaar/metayaar
cd /var/www/ecoshaar/metayaar
git clone <repository-url> .

2. Laravel settings

compose.yaml already sets the database, APP_ENV, APP_DEBUG, logging and PUBLIC_STORAGE_URL. Set the rest:

back/.env ← cp back/.env.example back/.env
APP_NAME=Metayaar

APP_URL=https://api.metayaar.com

# Login tokens expire after this many minutes (720 = 12 hours) for all users
SANCTUM_EXPIRATION=720

MAIL_MAILER=smtp

MAIL_PORT=587
MAIL_USERNAME=...
MAIL_PASSWORD=...
MAIL_FROM_ADDRESS=no-reply@metayaar.com
MAIL_FROM_NAME="Metayaar"

SMS_DRIVER=msgway
MSGWAY_API_KEY=...
MSGWAY_OTP_TEMPLATE_ID=...
Don't put quotes or extra spaces around values, and never commit either .env file. Lock them down with chmod 600 .env back/.env.

Build and start

The order matters: the store reads the app catalog from the API while it builds, so the API has to be running first.

  1. Build the Laravel image and generate the app key: 
    docker compose build api
docker compose run --rm --no-deps --entrypoint php api artisan key:generate --show
    Paste the output (base64:…) after APP_KEY= in back/.env.
    Never change APP_KEY later. Developers' bank details are encrypted with it.
  2. Start the database, API and nginx: 
    docker compose up -d --build db api scheduler queue nginx
docker compose ps          # api must show "healthy"
  3. Build and start the website and admin panel: 
    docker compose build website admin
docker compose up -d
  4. Watch the logs for errors: 
    docker compose logs -f api nginx website

First admin

Admin panel accounts are separate from website accounts. The command asks for a password.

docker compose exec api php artisan app:create-admin you@example.com --name="Your Name"
# other staff roles: --role=moderator or --role=curator
Never run php artisan db:seed without --class. It creates demo accounts whose password is password.

HTTPS certificate

Once DNS points at the server, request the certificate once by hand. After that, certbot renews it on its own.

docker compose run --rm --entrypoint certbot certbot certonly --webroot -w /var/www/certbot \
  --cert-name metayaar -d metayaar.com -d www.metayaar.com -d admin.metayaar.com -d api.metayaar.com \
  -m you@example.com --agree-tos --no-eff-email
docker compose restart nginx

# test renewal
docker compose run --rm --entrypoint certbot certbot renew --dry-run
Login only works over HTTPS (the login cookie is secure), and the desktop and glasses apps connect to https://metayaar.com. Without a valid certificate, nobody can log in or install apps.

ArvanCloud CDN

If the DNS records are in proxy (cloud) mode:

  • Connect Arvan to the origin over HTTPS. With HTTP, nginx redirects to HTTPS and you get a redirect loop.
  • Don't cache /download/*, /api/* or account pages. Use the "origin headers" cache mode.
  • Set Arvan's upload size limit above 12 MB (APK uploads arrive in 5 MB chunks).
  • If certbot fails, Arvan is probably redirecting /.well-known/acme-challenge/. Turn proxy mode off, get the certificate, then turn it back on.

Update, backup and everyday commands

Update to new code

cd /var/www/ecoshaar/metayaar
git pull --ff-only
docker compose up -d --build db api scheduler queue nginx
docker compose build website admin
docker compose up -d
docker image prune -f

The old site keeps serving while the new images build. A change to back/.env only needs docker compose up -d, with no rebuild.

Daily backup

/usr/local/bin/metayaar-backup.sh
#!/usr/bin/env bash
set -euo pipefail
cd /var/www/ecoshaar/metayaar
DEST=/backup/metayaar; DAY=$(date +%F); mkdir -p "$DEST"
docker compose exec -T db sh -c 'pg_dump -U "$POSTGRES_USER" "$POSTGRES_DB"' | gzip > "$DEST/db-$DAY.sql.gz"
docker compose exec -T api tar czf - -C /var/www/html/storage app > "$DEST/storage-$DAY.tgz"
tar czf "$DEST/env-$DAY.tgz" .env back/.env
find "$DEST" -type f -mtime +14 -delete

Make it executable with sudo chmod 700, then add 0 3 * * * /usr/local/bin/metayaar-backup.sh with sudo crontab -e.

docker compose down -v deletes the database and all uploads. To stop the stack, use docker compose down without -v.

Part 2

Desktop app downloads for each OS

The desktop app opens the store in a window and installs apps on a headset or glasses over USB with its own bundled adb. Users never install adb or drivers separately.

How downloads work

On the server, website/public/desktop and website/public/android are mounted straight into nginx and the website. The /download and /setup pages detect the visitor's OS and only list installers whose files exist in that folder. Copy a new file in and it shows up right away, with no rebuild or restart.

The file names must match exactly:

OSFileTypeFolder
WindowsMetayaar-win-x64.exeOne-click installer, includes the USB driverdesktop/
WindowsMetayaar-win-x64.zipPortable, no USB driverdesktop/
macOSMetayaar-mac-universal.dmgApple Silicon and Inteldesktop/
LinuxMetayaar-linux-amd64.debUbuntu, Debian, Mint, Pop!_OS; sets USB permissionsdesktop/
LinuxMetayaar-linux-x86_64.AppImageAny distro, no installdesktop/
Android glassesMetayaar-quest.apkThe on-device appandroid/
The Windows .exe is missing right now. website/public/desktop currently has only the Windows .zip. Windows users get the portable version without the USB driver, so many of them won't see their device. Build the .exe (next section) and publish it.

Build the installers for each OS

Build on your development machine, inside desktop/, with Node 22. Always set STORE_URL to the real store address. A build without it, or a -local- build, connects to a development machine, and users see the "could not connect" screen.

Linux

Builds on any Linux machine.

STORE_URL=https://metayaar.com \
  npm run release:linux
  • Makes the .deb and .AppImage

Windows

On Linux, the .exe needs wine (sudo apt install wine64). Without wine you only get the .zip.

STORE_URL=https://metayaar.com \
  npm run release:win
  • Or build it on GitHub Actions

macOS

Only builds on a Mac, or on GitHub Actions.

STORE_URL=https://metayaar.com \
  npm run release:mac
  • Makes the universal .dmg

All three at once: .github/workflows/build.yml builds Linux, Windows and macOS on their own runners. Run it from the Actions tab, or push a tag such as v0.2.0 to attach the installers to a GitHub release. Then pull them into the website folder:

cd desktop
npm run pull-release      # needs the gh CLI, signed in

release:* and pull-release both copy the files to website/public/desktop on your machine.

The glasses APK

Build a signed release APK. You need android/keystore.properties and the keystore file. Always keep the same key, because Android refuses updates signed with a different one.

cd android
./gradlew assembleRelease -PstoreUrl=https://metayaar.com
cp app/build/outputs/apk/release/app-release.apk ../website/public/android/Metayaar-quest.apk
Never publish app-debug.apk. It loads http://localhost:3000, not the real store.

Put the files on the server

scp website/public/desktop/Metayaar-* deploy@SERVER:/var/www/ecoshaar/metayaar/website/public/desktop/
scp website/public/android/Metayaar-quest.apk deploy@SERVER:/var/www/ecoshaar/metayaar/website/public/android/

Don't copy Metayaar-local-* files. Check each download:

for f in Metayaar-win-x64.exe Metayaar-win-x64.zip Metayaar-mac-universal.dmg \
         Metayaar-linux-amd64.deb Metayaar-linux-x86_64.AppImage; do
  printf '%-34s ' "$f"; curl -s -o /dev/null -w '%{http_code}\n' "https://metayaar.com/desktop/$f"
done

What users do on each OS

Windows

  • Run Metayaar-win-x64.exe, then accept the admin prompt once. It installs the app, adb and the USB driver.
  • Portable .zip: Extract All, run Metayaar.exe. If the device isn't found, use the .exe instead.

macOS

  • Open the .dmg and drag Metayaar to Applications. No driver needed.
  • On first launch, if "Apple could not verify…" appears: System Settings → Privacy & Security → Open Anyway, once.

Linux

  • .deb (recommended): sudo apt install ./Metayaar-linux-amd64.deb
  • AppImage: chmod +x it, then run it. On Ubuntu 24.04+, add --no-sandbox.
  • The AppImage can't set USB permissions; see Prepare the computer.
Part 3

Install the Android app on glasses that block installs

For glasses that refuse APK installs from the device itself. Every install goes from a computer over a USB cable, using adb.

Why ADB works when the glasses block installs

The "unknown sources" block only stops apps on the glasses from installing other apps. adb install from a computer doesn't go through that setting, so you can install both the Metayaar app and any store app over the cable.

Prepare the glasses (once)

Menu names differ a little between brands. The usual path is:

  1. Turn on developer mode. Settings → About device → tap Build number seven times.
  2. Turn on USB debugging. Settings → Developer options → USB debugging. If there's also an Install via USB option, turn it on too.
  3. Connect the cable to the computer. Use a data cable; many charging cables have no data wires, and the glasses won't appear at all.
  4. Allow the computer. When "Allow USB debugging?" appears on the glasses, tick Always allow from this computer and confirm.
The glasses need Android 10 or newer. Older versions fail with INSTALL_FAILED_OLDER_SDK. On Meta Quest, turn on developer mode from the Meta Horizon phone app: Devices → Headset settings → Developer mode (create an organization at developers.meta.com first).

Prepare the computer (once)

Recommended: install Metayaar Desktop from /download and log in. adb is inside the app.

Command line instead: install Android platform-tools (on Linux, sudo apt install adb) and check the connection. The glasses must show as device:

adb devices

Windows

Install the glasses maker's USB/ADB driver. Without it, Windows doesn't see the glasses as an ADB device. The desktop .exe only bundles a generic driver.

macOS

Nothing extra. macOS needs no driver for adb.

Linux

The .deb only adds USB rules for Quest (2833) and Pico (2d40). For other glasses, add the maker's vendor ID:

Linux: allow adb to open your glasses
# the 4 hex digits before ":" are the vendor ID, for example 1d6b
lsusb
# replace XXXX with that vendor ID
echo 'SUBSYSTEM=="usb", ATTR{idVendor}=="XXXX", MODE="0666", GROUP="plugdev"' \
  | sudo tee -a /etc/udev/rules.d/51-metayaar-headsets.rules
sudo udevadm control --reload-rules && sudo udevadm trigger
adb kill-server && adb devices

Install the Metayaar app on the glasses

Option A: with Metayaar Desktop (recommended)

  1. Connect the glasses and open Metayaar Desktop.
  2. Open the Metayaar for headset page (/quest) from the side menu.
  3. Click Install Metayaar on headset and wait for the success message.

Option B: with the adb command

# download it from the server, then install
curl -LO https://metayaar.com/android/Metayaar-quest.apk
adb install -r Metayaar-quest.apk          # must end with "Success"

# open it
adb shell am start -n ir.metayaar.store/.MainActivity

Log in to Metayaar on the glasses. The login is saved.

Login lasts 12 hours. Login tokens now expire after 12 hours (SANCTUM_EXPIRATION=720) for every account, so users on the glasses and in the desktop app have to log in again after that.

Optional: allow installs from inside the glasses

If you want to install apps later without a computer, grant the permission through adb:

adb shell appops set ir.metayaar.store REQUEST_INSTALL_PACKAGES allow
adb shell appops get ir.metayaar.store REQUEST_INSTALL_PACKAGES   # should print: allow

If the command fails, or installing from the glasses still doesn't work, the maker blocks it by policy. That's fine: install from the computer as below.

Install store apps on the glasses

Option A: "Install on headset" in Metayaar Desktop (recommended)

  1. Connect the glasses and open Metayaar Desktop. On an app page, next to the install button, you should see "Connected to …" with the glasses model.
  2. Log in to your account.
  3. Find the app under Apps and open its page.
  4. If it's a paid app you haven't bought, click Buy and install and finish the purchase.
  5. Click Install on headset. If several devices are connected, pick the glasses.
  6. The progress bar shows the download, then the install. "Installed" means it's done.

Option B: download the APK and install from the computer

  1. On the app page, click Download APK. It only appears for apps your account is allowed to download.
  2. Install it either in Metayaar Desktop on the Install APK from computer page (/install), where you can pick several files at once, or with: 
    adb install -r -g app-name.apk

-r replaces an installed version and keeps its data. -g grants the app's permissions up front, so the glasses don't need to ask.

Open, update and remove apps

Installed apps appear in the glasses' app list (on Quest-like systems, under Unknown Sources in the Library). If the launcher only shows approved apps, start them from the computer:

# the Metayaar app
adb shell am start -n ir.metayaar.store/.MainActivity
# any installed app, by package name
adb shell monkey -p com.example.game -c android.intent.category.LAUNCHER 1
# list installed apps to find a package name
adb shell pm list packages -3
# open one app's store page inside Metayaar
adb shell am start -a android.intent.action.VIEW -d metayaar://apps/<slug>

# update: install the new version over the old one (data stays)
adb install -r app-name.apk
# remove
adb uninstall ir.metayaar.store
adb uninstall com.example.game

An update must be signed with the same key and have a higher versionCode.

Who can install what

The server checks the account before every download, whichever install method you use.

AccountApps it can install
MemberPublished free apps, and paid apps they bought
DeveloperEverything above, plus their own apps in any state (draft, in review, rejected). Use this to test before publishing.
Moderator / adminEvery app in any state
Testing every app on one pair of glasses (for example, in the office): give that account the moderator role in the admin panel.
